# DATA Step Lab project guidance

- Read HANDOFF.md for user intent, architecture, current limitations, and validation gaps.
- Author the modular files under dist/. `dist/data-step-lab.html` is generated by `build-offline.py`; rebuild it after source changes.
- Preserve browser-local computation and single-file offline delivery. The application does not require a server, LLM, or Python to run; Python is currently used only for packaging.
- Interpret the supported SAS subset deliberately. Do not replace match-MERGE behavior with SQL join semantics. Unsupported features must fail clearly.
- Existing assertions are a baseline, not proof of SAS compatibility. Add useful edge-case fixtures for changed semantics; document actual SAS-reference provenance when available.
- Run relevant checks; the complete baseline suite is `npm test` or the four Node commands in README.md. Use Node 20+; the baseline was checked under Node 24.19.0.
- After source edits, run Python 3 packaging, then the offline package check. Actual Windows/browser validation is still needed.
- Keep logs and limitations honest. Report unavailable browser/SAS validation without claiming it passed.
- Do not introduce unrequested public publication, external data transmission, server processing, or credentials. No hosting identity is configured in this extracted working tree.
