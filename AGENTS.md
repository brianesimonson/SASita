# DATA Step Lab project guidance

- Read VALIDATION-STATUS.md, PROJECT-STATUS.md, START-HERE.md, and HANDOFF.md for user intent, architecture, current limitations, and validation gaps.
- Author the modular files under dist/. `dist/data-step-lab.html` is generated by `build-offline.py`; rebuild it after source changes.
- Preserve browser-local computation and single-file offline delivery. The application does not require a server, LLM, or Python to run; Python is currently used only for packaging.
- Interpret the supported SAS subset deliberately. Do not replace match-MERGE behavior with SQL join semantics. Unsupported features must fail clearly.
- Existing assertions are a baseline, not proof of SAS compatibility. Add useful edge-case fixtures for changed semantics; document actual SAS-reference provenance when available.
- Run relevant checks; the complete baseline suite is `npm test` or the four Node commands in README.md. Use Node 24+; the baseline was checked under Node 24.19.0.
- After source edits, run Python 3 packaging, then the offline package check. Run `npm run test:browser` when Chromium is available. Windows manual validation is still needed.
- Keep logs and limitations honest. Report unavailable browser/SAS validation without claiming it passed.
- Do not introduce unrequested public publication, external data transmission, server processing, or credentials. No hosting identity is configured in this extracted working tree.

- Use the existing checkout in isolated cloud tasks; do not create Git worktrees unless explicitly requested.
- Record milestones and verified testing gaps in PROJECT-STATUS.md; use small commits and feature branches for subsequent changes.
- GitHub is configured for brianesimonson/SASita. Push only when authorized by the user; do not reuse historical Site identities.

- Common formats and RAND scope are documented in docs/formats-conversions-rand.md. Preserve the explicit MT32 selection; do not label uniform/normal sequences SAS-identical without real SAS fixtures. Keep new modules included in the offline build.

- Program/folder workflows are documented in docs/project-files.md. Keep programmatic file access relative to a user-selected directory handle; never request permission silently during a run. Remember handles in browser storage without treating permission as permanent. Preserve staged exports, all-target preflight, explicit REPLACE, and honest partial-save reporting. Build the ZIP with python3 scripts/package-app.py after rebuilding HTML; keep the packaged demo verified.

- Native JSON libraries are documented in docs/native-tables.md. Preserve version/schema validation, scoped LIBNAME directories, cross-run disk refresh, alias read-after-write behavior, staged final table saves and inherited length metadata. Run test-libraries.mjs with the baseline suite. Keep the documented JSON Schema and library demo in the ZIP. The SPI PNG is an adapted user-supplied logo; keep it embedded for offline delivery.

- Plotting scope is documented in docs/charts.md. Keep Chart.js locally vendored and embedded, chart models data-only/in the worker, and no chart/dataset/title commits on program failure. Keep missing-value counts, limits, snapshot history, canvas cleanup and titled PNG downloads verified by test-charts.mjs and the browser suite. Charts are a deliberate SAS subset, not certified SAS visual/statistical equivalence.

- Portable wrapper demo scope is docs/portable-demo.md. Build generates dist/runtime-assets.mjs from actual runtime/portable files; preserve exact viewed/exported source. Run test-portable.mjs and browser ZIP-to-Python execution checks after changes. Keep current WORK snapshot semantics and external --project paths explicit, serialization before writes, all-target preflight and honest partial-save reporting. No per-program transpilation or multiuser sandbox claim.

- PROC MEANS scope is docs/means.md. Preserve default CLASS total/subtotal bit masks and _FREQ_/_STAT_ shapes, formatted grouping and per-variable missingness; do not default to NWAY. Run test-means and portable/browser checks. New SAS runtime validation remains pending; regenerate the six CSV/ZIP fixtures with scripts/package-means-validation.mjs after statistical changes. Edit examples/catalog .sas sources, then build to regenerate example-programs.mjs.

- PROC SURVEYSELECT/default RAND scope is docs/surveyselect.md and docs/random-numbers.md; deployment matrix is docs/procedure-support.md. Preserve exact uniform conversion, explicit MT32 and default initialization, automatic stratum seeds from a separate master stream, input ordering, retained NumberHits on expanded rows, staged native writes and all-or-nothing UI commits. Run test-surveyselect.mjs plus portable/browser checks. Original twelve SAS CSVs and focused 35-row probe are fixture evidence; do not replace them with generated predictions. Unsupported stratified REPS, formatted strata and legacy/PPS designs must fail clearly. NORMAL and broad hybrid/seed cases are not SAS-certified.

- NORMAL caches the unscaled second polar value per DATA step. UNIFORM calls and ignored STREAMINIT must preserve it; each NORMAL call applies its own parameters. Run test-normal.mjs, portable and browser checks after stream changes. fixtures/sas/normal-method-probe.json contains 52 actual printed normal HEX values, 28 uniform witnesses and SAS candidate summaries; do not conflate the printed JavaScript comparisons with all 2,048 SAS candidate values. Last-bit normal and broad seed/parameter/tail equivalence are not certified.

- PROC GLM scope is docs/glm.md. Preserve hierarchical complete-cell Type III block hypotheses, ordered CLASS indicator SOLUTION, effect-order Type I tests, staged ODS/P/R outputs, explicit rank/design limits. Run test-glm.mjs, portable and browser checks. Regenerate scripts/package-glm-validation.mjs after statistical changes; published tables and independent numerical fixtures are not a fresh SAS runtime certification.

- PROC PRINT scope is docs/print.md. Keep explicit, bounded observation reports separate from datasets; preserve OBS/FIRSTOBS ranges, VAR order, showObs/original observationNumbers, inherited formats, native reads and no source writes. Run test-print and browser/portable checks after changes.

- MEANS/GLM WEIGHT rules and formulas are docs/weights.md. Preserve different nonpositive-weight inclusion, count-vs-SUMWGT divisors, stable weighted QR/scaling, and unweighted fixture behavior. Run test-weights plus full/browser/portable checks; regenerate scripts/package-weight-validation.mjs after weighted statistical changes. Independent references are not actual weighted SAS fixtures.

- VALIDATION-STATUS.md is the current pending/completed test registry. Read it when asked about outstanding validation; WEIGHT-SAS received actual results on 2026-10-28: ten GLM groups pass; five MEANS groups exposed only _FREQ_ differences, fixed locally in v0.4.18, awaiting corrected SAS rerun. Preserve this partial status and the original kit/evidence. Update statuses only from actual evidence.
- Editor completion is docs/editor-completion.md and dist/completion.mjs. It is authoring assistance, not runtime syntax: datasets complete after a library dot, variable shortcuts replace the whole qualifier with a bare variable. Use metadata only, never rows/files/permissions or program execution. Keep normal Tab and Ctrl+Space behavior, comments/strings/macros guards, dirty state and offline builds verified.

- Continue normal user-facing updates on feature/editor-dataset-completion so the user can Fetch/Pull into their local app folder. Preserve main and milestone tags; do not silently move routine updates to another branch.
- The ?? starter and automatic fragment menus cover all nine supported procedures. Keep it a small data catalog alongside syntax-help, using the existing popup; no runtime syntax change. Test statement boundaries, comment/string guards, used/order rules and executable filled templates in test-statement-templates.mjs.

- Automatic assistance uses the shared catalog in syntax-help and pure context/metadata helpers in completion.mjs. Keep used/alias/role suppression, free-form editing, plain Enter behavior, and no observation/file/network access. Test all nine supported headers and executable assembled programs in test-incremental-completion.mjs, plus browser chains. Avoid silently extending runtime SAS syntax or statistical claims.
